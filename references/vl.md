# PaddleOCR-VL 接口

VL 在两条工作流里的角色见 [SKILL.md](../SKILL.md)「识别来源各管什么」。本页只写调用、起稿工具和已知局限。

## 调用

```powershell
python -X utf8 <skill>/scripts/paddle_api.py configure
python -X utf8 <skill>/scripts/paddle_api.py submit <书>/<原件>.pdf -o <书>/_数据/VL
```

- 子命令：`configure`（本机隐藏输入 token）、`submit`、`check-models`、`use-model`。只在真要调用时处理凭据；已有逐页缓存直接用。模型查新不是整理前提。
- PDF 会上传到百度服务器，需有本次任务的授权。
- 超过 100 页自动分块，失败块有限重试，重跑只补缺页。实际用的模型和结果看 `_run.json` 与错误日志，不按旧文档猜版本。
- 免费额度：每用户每模型每日 20000 页（2026-10-16 核对），以服务实际限制为准。

## 按页起稿：vl_build.py

命令见 [historical-editions.md](historical-editions.md)。

- `build` 默认保守：始终保留原页序锚点；原件页码未核时不猜成印刷页；候选页眉、注区和疑似编造内容保留为待核项；不自动改卷号。
- `pages` 子命令做页码候选分析。人工核定后，才把它的报告作为 `--pages-report` 输入。
- VL 原始 `number` 块的文字存在整理报告的 `_sourcePageLabels` 里；需要原书页码/叶码时核图后在正文另标 `p` / `leaf`。
- 无标点白文不补标点。默认不识别字号小字，不靠编号开头自动认脚注。
- `--legacy-heuristics` 保留旧版结构候选功能（分隔线判脚注、字号判夹注、书眉等），只在确需精细注区/书眉/字号恢复、且抽样验证过时用。即使开启，重复卷号也只列候选，可疑正文保留待核，不截断。

## 已知局限

- VL 可能把原书异体写成通行字，漏后引号、书名号间的顿号，在空白页或透印处编造文字。
- MinerU 能提供区域框、部分读序、标点和独立列框，但会把正文归为页眉、漏分标题和注区。云端结果与开源主分支版本可能不同。
- 两家分歧回原图核，不拿第二读者直接覆盖正文。

## 历史小样本

- 《黄道周集》4 页核图：MinerU 只比汉字 84.9%，按列明异体折叠 88.1%；VL 对应 96.7%、99.6%。
- 《黄道周集》《明通鉴》各 10 页：MinerU 块内竖排读序多能保留，但有标题、卷名和注误分类；VL 某些页有编造。

这些不是全书准确率，也不能外推到手抄本；用户的书要按自己的页样本核实。
