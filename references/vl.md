# PaddleOCR-VL：识字来源与第二读者

按 SKILL.md 的两条材料工作流使用，不按横竖排把现代点校古籍和影印古籍混为一类。

- **A：现代出版物**通常由 MinerU 提供原生结构，VL 作第二读者。现代竖排本若 MinerU 文字失效，可用 VL 文字或按页原稿作起点，但仍恢复该出版物的实际注释和图表；不因此降低到 B 的验收。
- **B：非现代排印古籍**常用 VL 作按页文字来源，看典作第二读者，MinerU 输出中的可用框和读法也可辅助。不要求通用结构适配层或完整复刻 MinerU。默认只需页级核字；目录层级按 [toc-headings.md](toc-headings.md) 处理。

接口使用 `paddle_api.py configure / submit / check-models / use-model`，token 在本机隐藏输入保存，不贴聊天。只有实际需调用时处理凭据；已有逐页缓存直接复用。PDF 会上传到百度服务器，需有当前任务授权。未使用的模型查新不是整理前提。

```powershell
python -X utf8 scripts/paddle_api.py submit <书>/书.pdf -o <书>/_数据/VL
```

超过 100 页自动分块，失败块有限重试，重跑只补缺页；查看 `_run.json`、错误日志和实际模型，不用旧文档猜本次版本。历史核对的免费额度为每用户每模型每日 20000 页（2026-10-16），以实际服务限制为准，不在本页反复硬编码更多版本信息。

## 按页起稿

`vl_build.py build` 默认采用保守整理：原页序锚点始终保留，原件页码未核时不猜成印刷页；候选页眉、注区与疑似编造内容保留为待核项，不自动改卷号。命令见 [historical-editions.md](historical-editions.md)。`pages` 子命令是页码候选分析，人工核定后才将其作为 `--pages-report` 输入；本书目录页码不是 PDF 页序。

原始 `number` 块的文字保存在整理报告 `_sourcePageLabels`，需要原书页/叶码时核图并在正文另标 `p` / `leaf`。无标点白文不补标点。默认不识别字号小字，不靠编号开头自动认脚注。

`--legacy-heuristics` 保留旧版高级结构候选功能，只有确需精细注区/书眉/字号恢复并经过抽样验证时才选用；不是 B 的默认路径。即便开启，重复卷号也仅列候选，不直接改文字，疑似异常正文也保留待核，不静默截成前30字。

## 识字与结构的已知局限

VL 可能把原书异体写成通行字，漏后引号和书名号间顿号，在空白、透印处编造；看典也会漏标点和倒读条目号。两家分歧回到原图，不直接拿第二读者覆盖正文。

MinerU 能提供区域框、部分读序、标点及独立的列框，但有正文被归为页眉、标题/注区漏分等情况。先判断哪些信息可用，不能以字准或有框代替结构验收。云端结果与开源主分支版本可能不同。

## 历史小样本记录

《黄道周集》4 页核图：MinerU 只比汉字84.9%、按列明异体折叠88.1%；VL 对应96.7%、99.6%。这不是全书准确率，也不能外推手抄本。另测《黄道周集》《明通鉴》各10页：MinerU 块内竖排读序多能保留，有标题、卷名和注误分类；VL 某些页有编造。看典10页已接通，单页423字核图全匹配，但仍有标点/数字错误。用户的书需按自己的页样本核实。

复杂结构恢复仅在用户需要时参考 [structure-audit.md](structure-audit.md)，文字核对见 [ai-judging.md](ai-judging.md)。
