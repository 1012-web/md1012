# PaddleOCR-VL：横排书的第二位读者，竖排书的底稿

在 SKILL.md 开工流程指到这里时读取。

## 它是什么、在流程里干什么

PaddleOCR-VL 是视觉语言模型（0.9B 参数）：看整页图、先做版面分析（分出标题、正文块、页下注），再像语言模型那样把每块的字「写」出来，懂阅读顺序和上下文。PaddleOCR 官方称对竖排古籍做过优化。本 skill 经官方 API（`paddle_api.py`，百度飞桨星河社区）调用，用户什么都不用装；代价是 PDF 会上传到百度服务器，每日有页数上限。

| | MinerU | PaddleOCR-VL |
|---|---|---|
| 认字依据 | 版面 + 识别 | 看字形也看上下文 |
| 坐标 | 行框（VLM 后端常一段一条，要按墨迹再切） | 只有块框 |
| 长处 | 结构（标题、脚注、跨页） | 字全、标点注号全、竖排读得好、能读回 MinerU 整块漏掉的块 |
| 短处 | 竖排认字差（异体、形近字错得多）、篇题与卷名常漏、注常被当页眉丢掉 | **按上下文「规范化」**：原书「遥産悦録」写成「遙產悅錄」，也可能把原书误印「改对」；嵌套引号『』写成「」；**大面积漏后引号**（《明通鉴》前引号 2034、后引号 1385）；**删掉书名号之间的顿号**（原书「《易》、《詩》」）；在空白、透印处**凭空编造** |

两种用法：

- **横排书：第二位读者。** 与 MinerU 同时跑，`vl_compare.py --vl-dir` 拿它和成品正文逐页比，分歧就是疑字，交 AI 看原图判定（[ai-judging.md](ai-judging.md)）。不许拿 VL 的读法直接改正文。
- **竖排书：底稿。** `vl_build.py` 把 VL 逐页结果整理成 Markdown，之后必须做结构核查；**MinerU（vlm 后端、`--ocr on`）同时跑，当第二位读者**：`vl_compare.py --mineru` 出疑字、疑似 VL 编造、补标点线索三份清单。

### 竖排书为什么拿 MinerU 当第二读者（2026-10 实测）

《黄道周集》10 页、《明通鉴》10 页，MinerU vlm 后端对 VL-1.6：

- **读序**：块内竖排列序、字序都对（「MinerU 不能读竖排」的印象不对）；偶有一列串到别的块。
- **认字**：明显比 VL 差（鯢→鯤、齷齪→齦齦、鴞→鴨），还会写成旧字形；但也揪出过 VL 的错（「譖」VL 读成「譜」，「二篇」VL 读成「一篇」）。
- **编造**：两本 20 页里 **0 处**；同样的页 VL 编造了 4 页。所以「VL 有、MinerU 同页完全没有」的成段文字值得看原图。
- **标点**：读出的引号全部配对、内层『』也读出，保留书名号之间的顿号。pipeline 后端几乎读不出标点，不用。
- **结构**：卷名、文体标签、短纲文行常被当成页眉丢掉，注时有时无、注号常读错——所以只当第二读者，不当底稿。

同样做过对照、不用的：PP-OCRv6（竖排约一半的列读成日文假名乱码）、PP-StructureV3（大半正文块读成空）、VL-1.5（官方 API 交 1.5 的任务服务端一律失败）。

## 调用

```text
python paddle_api.py configure                                    # 首次：隐藏输入存令牌
python paddle_api.py submit <书>/书.pdf -o <书>/_数据/VL           # 每页一个 pNNNN.json，已有的页跳过
python paddle_api.py check-models                                 # 用户同意定期检查时：最多每 30 天查一次新模型
python paddle_api.py use-model PaddleOCR-VL-1.7                   # 用户点头换模型
```

- 令牌在星河社区「访问令牌」页（`https://aistudio.baidu.com/account/accessToken`）取，注册登录后可见。让用户在自己的终端跑 `configure`，不贴进聊天。
- 默认模型 `PaddleOCR-VL-1.6`（2026-10 实测线上已有 1.6，比官方文档写的 1.5 新）。`check-models` 拿一张空白页按更高版本号试交，线上对不存在的模型名当场拒绝（code 10007），不花额度；查到新的只报告，换不换由用户定。
- **免费额度（2026-10-16 核对官方配额说明，文档 2026-09-08 版）**：每个用户、**每个模型**每日最多解析 **20000 页**，各模型分开计；超了返回 429（异步任务接口文档另列错误码 12001「已达每日页数上限」）。单个文件建议不超过 1000 页，超过只解析前 1000 页；本地上传单文件不超过 50 MB。要更多可填官方问卷免费申请提升。官方没有用量查询接口，`paddle_api.py` 只在本机记当日已交页数。
- 大文件自动按 100 页一块、45 MB 以内切开分批交，原 PDF 不动；中断后重跑即续。
- 速度实测：7 页约 1 分钟，8 页约 40 秒（排队时间不定）。

## 竖排书：以 VL 作底稿（vl_build.py）

- `pages`：推断每页印刷页码。VL 读页码噪声大（「O」「111」「！！！！」），竖排页码「一三」常只读出「三」、连续几页自洽地错；插页又让偏移中途变化。规则：可解析且与邻页偏移一致才采信；≤7 页的一小段偏移与前后两段都不同、而前后两段相同，判为误读丢掉；两可信页偏移相同则中间按它补；篇首不印页码的页顺延 2 页以内。《黄道周集》推出：物理 1–9 无页码（封面版权简目）、10–16 目录 1–7、17–98 前言 1–82、99 起正文。
- `pages` 报告的 `unknownReasons` 写明每个推不出页码的页的原因。全书第一个可信页码之前、没有成段文字的页（封面、书名页）不顺延页码——分册本页码接着上册，封面会被推成 1173 这类假页码。
- `build`：按分段写成几个文件。页下注以**分隔线**为准（页面图上又细又长、两侧空白的墨线，竖排是竖线）——只看注号开头会把「（一）泛濫詩賦」这类小标题当成注；线那一侧至少一块以注号开头才认（版权页的表格线也是细长线）。VL 有时把注区标成 footer（页脚）：以注号开头的 footer 块按注处理，不当书口删。VL 读正文注号很不稳定（试水前言 65 条注只有 18 条读到了注号），读丢的留 `<!--?fnref n-->`，之后看原图放（`note_tasks.py`）。测到细长线却没认出注的页列进报告 `_ruleWithoutNotes`：可能是专名线、波浪线，也可能是注号全读丢的注区，结构核查时逐页看。
- **没有页下注的书**（注是段内夹排的小字，如《明通鉴》的【考異】）：分隔线一条也认不出注是正常的，不必做注区核对；夹注按段落照录，字号区分不可靠时不标 `<small>`。
- **条目号**：编年体点校本条首的小号阿拉伯数字（「10夏，四月」）。并非所有点校本都有。段首、句末或汉字之后的 1–3 位数字不算「编造」（曾因此有 1239 段正文被整段扣掉）；以条目号开头的段不升标题、不与上页末段接。报告提示「疑似带条目号」时问用户，开 `--item-numbers` 才套 `<sup class="item">`，每个都记进报告 `_itemNumbers` 备查。
- **书眉**：页边重复的短块（篇名、页码）当页眉丢掉。逐页变化的书眉（「明通鑑卷三十四 紀三十四 憲宗成化十八年（一四八二） 一一九七」）按开头几个字认出前缀：页边的整块删掉；夹进句子里的，只在「前缀 + 卷次年号 +（公元年）+ 本页页码」整串对上时删去。每一处都记进报告 `_headsRemoved`，交付前抽查。读乱的书眉认不出，要靠结构核查的残留扫描。
- **小字**：按字号比本页正文小两成以上标 `<small>`。短段只有一两列，列宽量不准，误标多：某一段小字超过一成半时自动停用，超过 5% 时报告提醒抽查，多数误标就 `--no-small` 重跑。
- 标题层级：VL 的标签只是线索，主要看位置、长短、有无句读。竖排的篇题比正文低三四格起排（上沿在页高 17%–32%）、短、无句读；「卷N」在右侧第一列且本页另有文体标签或篇题才算卷名（书目页里的「卷二十 説」不算）；VL 标成大标题的「明通鑑卷四十二」也算。卷号按出现顺序校正：读出的卷号不大于上一卷就改成上一卷 +1（书名页的「卷三十四至五十」是范围，不算）。编年体每帝之首的帝号行（「……皇帝」）为二级。前言里「一、」「（一）」分二、三级；篇题后原书小字的年月、「凡三章」「節録」用 `<small>` 标出。年号、文体字这几张表是照《黄道周集》等书写的，别的书对不上时只会漏认、不会误删，漏认的在结构核查里补。
- 图、表按 VL 块坐标从原 PDF 裁出存 `images/` 原位嵌入；VL 把文字区当成图（`chart`）时留 `<!--?chart-->` 待补录；段落字号比本页正文小两成以上的（「洪思曰」夹注）用 `<small>` 标出。
- **VL 会凭空编造**：物理 103 页一处空白写出「1986年4月24日，中国政府拨款……」并重复十遍，110 页写出「A 1000-A 1000-…」。整理时三条硬特征拦下（简体专用字 ≥3、同一串数字字母重复 ≥4 次、同一句重复 ≥3 次），写成 `<!--?vl-suspect 原因：前30字…-->` 并列入报告，交人工核对原图。
- 页边重复出现的短块（竖排页边的篇名、页码）当页眉丢掉：VL 常把它们标成正文，接段时会夹进句子中间。
- 本书字形表（`--variant-equivalent 黄黃 …`）把 VL 的通行字形改回原书字形；只收逐组看原图核实过的异体对，核实记录写进校注。
- **vl_build 之后必须做结构核查**（[structure-audit.md](structure-audit.md)）：《黄道周集》整本做完后，仍有 61 条注漏收或混进正文、17 个篇题读丢、清单页漏读约三分之二。要逐页核对注区、拿目录对篇题、清单页整页重录、扫残留。

整条流程（`<书>` = 书文件夹）：

```text
1. python paddle_api.py submit <书>/书.pdf -o <书>/_数据/VL
   python mineru_api.py submit <书>/书.pdf -o <书>/_数据/MinerU原始 --ocr on        （第二读者，同时交）
2. python vl_build.py pages --vl-dir <书>/_数据/VL --pages 1-N --report <书>/_数据/过程报告/_vl_pages.json
   python vl_build.py build --vl-dir … --pdf <书>/书.pdf --pages-report … --segment 1-9:00-卷首.md --segment 10-N:01-正文.md \
       --variant-equivalent 黄黃 … --writing-mode vertical-rl --out-dir <书>/_数据/过程报告/vl稿 [--item-numbers] [--no-small]
   → 读 <书>/_数据/过程报告/_vl_build_report.json 的 _warnings，逐条处理；把 vl稿 复制到书文件夹当成品起点
3. 结构核查（structure-audit.md）：清单页与目录重录 → 目录对篇题 → 注区核对与补注 → 残留扫描 → renumber、notes-count
4. python diff_report.py --before "<书>/_数据/过程报告/vl稿/*.md" "<书>/0*.md"
5. python line_map.py --pdf <书>/书.pdf --md … --vl-dir <书>/_数据/VL --writing-mode vertical-rl --out <书>/_数据/逐行映射
6. python vl_compare.py --book <书> --line-map <书>/_数据/逐行映射/line-map.json --mineru "<书>/_数据/MinerU原始/<卷>|1" --variant …
   → 疑字、疑似 VL 编造、补标点线索
```

## 实测（《黄道周集》4 页试水：竖排繁体、中华书局 2017 排印本、扫描件）

以逐页对原图核过的试水稿为标准（准确率 = 1 − 编辑距离 / 标准字数）：

| 来源 | 只比汉字 | 汉字（异体折叠） | 汉字＋标点（不计注号） | 标点读出 |
|---|---|---|---|---|
| MinerU | 84.9% | 88.1% | 88.8% | 245/271 |
| PaddleOCR-VL | 96.7% | 99.6% | 99.9% | 269/271 |

- MinerU 整块漏掉的第 1 页署名与两条页下注，VL 全部读回；MinerU 的「治生活產」（原书「治生治産」）VL 读对。
- 原书字形 8 组异体里，VL 只「爲」全对，「産悦録遥」全被改成通行字形——所以保留原书字形的书要靠本书字形表改回。
- 2026-10 线上 VL-1.6 与先前测的同版模型块框一致（35 块全部重合），正文文字相似度 0.997–1.0。
