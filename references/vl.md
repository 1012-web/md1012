# PaddleOCR-VL：第二位读者，竖排书的底稿

在 SKILL.md 开工流程指到这里时读取。

## 它是什么、在流程里干什么

PaddleOCR-VL 是视觉语言模型（0.9B 参数）：看整页图、先做版面分析（分出标题、正文块、页下注），再像语言模型那样把每块的字「写」出来，懂阅读顺序和上下文。PaddleOCR 官方称对竖排古籍做过优化。本 skill 经官方 API（`paddle_api.py`，百度飞桨星河社区）调用，用户什么都不用装；代价是 PDF 会上传到百度服务器，每日有页数上限。

| | MinerU | PaddleOCR-VL |
|---|---|---|
| 认字依据 | 版面 + 识别 | 看字形也看上下文 |
| 坐标 | 行框（VLM 后端常一段一条，要按墨迹再切） | 只有块框 |
| 长处 | 结构（标题、脚注、跨页） | 字全、标点注号全、竖排读得好、能读回 MinerU 整块漏掉的块 |
| 短处 | 竖排会整块漏读、丢注号 | **按上下文「规范化」**：原书「遥産悦録」写成「遙產悅錄」，也可能把原书误印「改对」；嵌套引号『』会写成「」；偶尔凭空编造 |

两种用法：

- **横排书：第二位读者。** 与 MinerU 同时跑，`vl_compare.py` 拿它和成品正文逐页比，分歧就是疑字，交 AI 看原图判定（[ai-judging.md](ai-judging.md)）。不许拿 VL 的读法直接改正文。
- **竖排书：底稿。** 不调 MinerU，`vl_build.py` 把 VL 逐页结果整理成 Markdown，之后必须做结构核查。

## 调用

```text
python paddle_api.py configure                                    # 首次：隐藏输入存令牌
python paddle_api.py submit <书>/书.pdf -o <书>/_数据/VL           # 每页一个 pNNNN.json，已有的页跳过
python paddle_api.py check-models                                 # 用户同意定期检查时：最多每 30 天查一次新模型
python paddle_api.py use-model PaddleOCR-VL-1.7                   # 用户点头换模型
```

- 令牌在星河社区「访问令牌」页（`https://aistudio.baidu.com/account/accessToken`）取，注册登录后可见。让用户在自己的终端跑 `configure`，不贴进聊天。
- 默认模型 `PaddleOCR-VL-1.6`（2026-10 实测线上已有 1.6，比官方文档写的 1.5 新）。`check-models` 拿一张空白页按更高版本号试交，线上对不存在的模型名当场拒绝（code 10007），不花额度；查到新的只报告，换不换由用户定。
- 大文件自动按 100 页一块、45 MB 以内切开分批交，原 PDF 不动；中断后重跑即续。
- 速度实测：7 页约 1 分钟，8 页约 40 秒（排队时间不定）。

## 竖排书：以 VL 作底稿（vl_build.py）

- `pages`：推断每页印刷页码。VL 读页码噪声大（「O」「111」「！！！！」），竖排页码「一三」常只读出「三」、连续几页自洽地错；插页又让偏移中途变化。规则：可解析且与邻页偏移一致才采信；≤7 页的一小段偏移与前后两段都不同、而前后两段相同，判为误读丢掉；两可信页偏移相同则中间按它补；篇首不印页码的页顺延 2 页以内。《黄道周集》推出：物理 1–9 无页码（封面版权简目）、10–16 目录 1–7、17–98 前言 1–82、99 起正文。
- `build`：按分段写成几个文件。页下注以**分隔线**为准（页面图上又细又长、两侧空白的墨线，竖排是竖线）——只看注号开头会把「（一）泛濫詩賦」这类小标题当成注；线那一侧至少一块以注号开头才认（版权页的表格线也是细长线）。VL 读正文注号很不稳定（试水前言 65 条注只有 18 条读到了注号），读丢的留 `<!--?fnref n-->`，之后看原图放（`note_tasks.py`）。
- 标题层级：VL 多把篇题标成正文。竖排的篇题比正文低三四格起排（上沿在页高 17%–32%）、短、无句读；「卷N」在右侧第一列且本页另有文体标签或篇题才算卷名（书目页里的「卷二十 説」不算），卷号按出现顺序校正；前言里「一、」「（一）」分二、三级；篇题后原书小字的年月、「凡三章」「節録」用 `<small>` 标出。
- 图、表按 VL 块坐标从原 PDF 裁出存 `images/` 原位嵌入；VL 把文字区当成图（`chart`）时留 `<!--?chart-->` 待补录；段落字号比本页正文小两成以上的（「洪思曰」夹注）用 `<small>` 标出。
- **VL 会凭空编造**：物理 103 页一处空白写出「1986年4月24日，中国政府拨款……」并重复十遍，110 页写出「A 1000-A 1000-…」。整理时三条硬特征拦下（简体专用字 ≥3、同一串数字字母重复 ≥4 次、同一句重复 ≥3 次），写成 `<!--?vl-suspect 原因：前30字…-->` 并列入报告，交人工核对原图。
- 页边重复出现的短块（竖排页边的篇名、页码）当页眉丢掉：VL 常把它们标成正文，接段时会夹进句子中间。
- 本书字形表（`--variant-equivalent 黄黃 …`）把 VL 的通行字形改回原书字形；只收逐组看原图核实过的异体对，核实记录写进校注。
- **vl_build 之后必须做结构核查**（[structure-audit.md](structure-audit.md)）：《黄道周集》整本做完后，仍有 61 条注漏收或混进正文、17 个篇题读丢、清单页漏读约三分之二。要逐页核对注区、拿目录对篇题、清单页整页重录、扫残留。

整条流程（`<书>` = 书文件夹）：

```text
1. python paddle_api.py submit <书>/书.pdf -o <书>/_数据/VL
2. python vl_build.py pages …  →  python vl_build.py build … --writing-mode vertical-rl
3. 结构核查（structure-audit.md）：清单页与目录重录 → 目录对篇题 → 注区核对与补注 → 残留扫描 → renumber、notes-count
4. python line_map.py --pdf <书>/书.pdf --md … --vl-dir <书>/_数据/VL --writing-mode vertical-rl --out <书>/_数据/逐行映射
   （要带文字层的 PDF 时加 --spec，再 pdf_textlayer.py build；竖排自动整列一行）
```

## 实测（《黄道周集》4 页试水：竖排繁体、中华书局 2017 排印本、扫描件）

以逐页对原图核过的试水稿为标准（准确率 = 1 − 编辑距离 / 标准字数）：

| 来源 | 只比汉字 | 汉字（异体折叠） | 汉字＋标点（不计注号） | 标点读出 |
|---|---|---|---|---|
| MinerU | 84.9% | 88.1% | 88.8% | 245/271 |
| PaddleOCR-VL | 96.7% | 99.6% | 99.9% | 269/271 |

- MinerU 整块漏掉的第 1 页署名与两条页下注，VL 全部读回；MinerU 的「治生活產」（原书「治生治産」）VL 读对。
- 原书字形 8 组异体里，VL 只「爲」全对，「産悦録遥」全被改成通行字形——所以保留原书字形的书要靠本书字形表改回。
- 2026-10 线上 VL-1.6 与先前测的同版模型块框一致（35 块全部重合），正文文字相似度 0.997–1.0。
