# AI 看原图判定 OCR 疑字

逐字映射里的 OCR 疑字有两档：「两家读法不一致」（MinerU 与 PaddleOCR 读得不同，错字最集中）与「两家一致但把握低」
（多是认对的生僻字）。本流程让看得懂图的模型逐个看原书图像判定，再按用户定的规则改正文、写校勘账本（笔记1012 插件）。
只在用户要求时做。以一本书为单位，一口气做完的流程如下。

## 整本流程

1. **截图**：`python -X utf8 scripts/doubt_crops.py <书文件夹> 1000 <输出目录>`。读书文件夹里的
   `校勘/<书名> OCR疑字.md`（先在插件里生成或更新）与 `_数据/`，两档都收（manifest 的 `kind` 为 `disagree` / `low`），
   按逐字映射截原图（整行附近 + 单字放大），每 5 个拼一张 `sheet-N.png`，写 `manifest.json`。只读笔记库。
2. **并行判定**：按约 50 个字（10 张拼图）一批，**每批一个全新子代理**，几批同时跑（一本约 300 字分 6 批，每批一两分钟）。
   子代理只把结果写成 `judgement-bK.json`，回报一行计数，不回贴表格，免得撑满主会话。
   发给子代理的提示词与结果格式用现成模板 [judging-prompt.md](judging-prompt.md)，填好书名、编号范围和「本书注意」即可。
3. **合并与过目**：`python -X utf8 scripts/merge_judgement.py <输出目录>` 合并目录里全部 `judgement-bN.json`（批数不限）为 `judgement.json`，
   按「原字→改作」分组列出要改的（把握高的 B/C）、原书误植、把握低的清单。编号重复、缺号、字段不全时它只列问题、不写文件，
   让那一批补齐再合并。主会话过一遍分组：专名、异体、常用字改得合不合文意。
4. **执行**：在用户的 Obsidian 里经命令行 eval 跑 `scripts/apply_judgement.js`（需要笔记1012 插件）：
   ```
   window.__judgement = { dir: "<输出目录>", variants: "<keep|normalize，按该书选定的异体字方针>", by: "AI 看原图判定" };
   eval(require("fs").readFileSync("<skill>/scripts/apply_judgement.js", "utf8"))
   ```
   结果在 `window.__judgementResult`（`applied` 改字、`verified` 认可、`skipped` 把握低未动、`mismatched` 位置对不上）。
   执行前把正文备份一份到输出目录。
5. **把握低的交给用户在对话里判**：`python -X utf8 scripts/pending_sheet.py <输出目录> <编号,编号,…>` 把这些字拼成一张图
   （每处标编号、书上页码、PDF 页码、正文现作），发给用户；用户回一行结论（如「66 入，184 剌」），写成 judgement
   （`by: "用户判定"`、依据「用户看原图截图判定」）再跑 `apply_judgement.js`。只挑「正文可能要改」的几处给用户，
   正文已是规范写法、只是扫描件看不清的，归一类请用户整批放行。
6. **整批放行**：用户同意后，在 Obsidian 里跑 `scripts/verify_remaining.js`
   （`window.__verifyRemaining = { title: "<书名>", by: "用户认可（未核纸本）", basis: "…" }`），
   按当前清单的前后文把剩下的全部认可，清单清零。用户翻纸本核对的个别字用 `scripts/verify_by_owner.js`
   （`window.__ownerVerify = { dir, numbers: [17, 28], basis: "纸本原书作入" }`），判定者记「用户核对纸本原书」；
   它在当前清单里按前后文找回这个字，不依赖截图时的位置，先加 `dryRun: true` 看找到的是不是那一处。

## 书不在 Obsidian 库里、或不经插件时

上面第 1、4、6 步依赖笔记1012 插件（读插件生成的疑字清单、在 Obsidian 里写校勘账本）。书文件夹不在库里（如还在整理阶段），或用户只要 Markdown 与校注时，改用两个独立脚本。第 2、3、5 步不变。

1. **截图**：`python -X utf8 scripts/doubt_sheets.py crops --book <书> --out <书>/_数据/疑字判定`。直接读映射里的疑字，横排截整行、竖排截整列，都用红线夹住疑字；竖排的拼图是 5 格横排，每格上面放大、下面整列。manifest 字段同上，多了 `from/to`（UTF-16 偏移）。
2. **执行**：`python -X utf8 scripts/apply_doubts.py --book <书> --dir <判定目录> --variants <keep|normalize>`。执行规则与下表相同。改前核对该处仍是原字，同一文件从后往前改，改前备份。`apply-report.json` 的 `changed` 可直接转成校注的改字附表。要整段处理的编号（混进正文的注文、要整页重录的页）用 `--skip`、`--skip-file` 跳过，交给 [structure-audit.md](structure-audit.md)。
3. **交用户**：要拍板的编号按性质分组写成 JSON（如「原书疑似印错」「疑漏字」「生僻字形」「字形难辨」），`doubt_sheets.py owner --dir <判定目录> --groups groups.json` 出带编号、页码、两家读法的拼图，发给用户；只是笔画细看不清、正文已是原书字形的，归一类请用户整批放行。

判定以后、执行以前，正文不要先动别处。偏移会挪，执行时就对不上位置了。

## 判定原则

完整的判定说明在 [judging-prompt.md](judging-prompt.md)。最要紧的一条：**以原图上印的字为准，上下文只作辅助**——曾凭上下文把原书印的「觶」猜成「觿」。
某本书扫描件有已知的特殊情况（见「各书实例」）时，写进那本书提示词的「本书注意」，不当通用规则。

## 执行规则（用户定）

| 判定 | 处理 |
|---|---|
| 把握低，或 D | 不动，交用户（第 5、6 步） |
| A | 认可此字，账本记判定者与依据 |
| A 且 `misprint` | **照录原书，另出校记**：正文不改，校勘记「照录原书的校记」写「原书作X，疑为Y之误」 |
| B / C | 改成原书的字，校勘记「判定与依据」写判定者与依据 |
| 有 `variant` | 按开工时用户选定的异体字方针（SKILL.md「异体字方针」，不设默认）：`variants: normalize` 正文用规范字，校记「原书作𫩫（嚈的异体），改作规范字」；`keep` 正文用原书字形，校记「规范字作嚈」 |

判定者要区分「AI 看原图判定」「用户判定」「用户核对纸本原书」「用户认可（未核纸本）」，读正文的人与 AI 都能看出哪些字经人核过。

## 技术要点

- **位置会挪动**：截图时记的是 UTF-16 偏移。执行时前面改过字、尤其换成扩展区的字（如「顗」→「𫖮」，占两个 UTF-16 单位），
  后面的字会整体挪一位。`apply_judgement.js` 在位置对不上时按前后四字在原位附近找回；仍找不到才记 `mismatched`，不会改错地方。
  上下文里的字本身也可能已改过（如前文「呎」已改成「嚈」），这时要按当前正文重写上下文再找。
- **插件侧**（笔记1012 f554597 起）：改过的字不再按「把握低」标出；认可记录的前后文一侧因附近改字变了，另一侧对得上仍算认可。
- 同一个错字常在一本书里反复出现（古代史编下「嚈哒」30 处），判定时一眼能看出同一字形，合并时按「原字→改作」分组核一次即可。

## 异体字

- 字形收进 Unicode 就能直接打、直接存（例：嚈的类推简化 𫩫 = U+2BA6B，扩展 E 区）。查码位：Unicode Unihan
  `https://www.unicode.org/cgi-bin/GetUnihanData.pl?codepoint=<码位>` 的 kSimplifiedVariant 等字段，或字统网 zi.tools。
- 显示要字体支持扩展区：Windows 自带「宋体-ExtB」（simsunb.ttf）含 𫩫，Obsidian 会自动回退使用。
- 没收进 Unicode 的字形只能写部件描述式（`⿰口厌`），正文用规范字，校记里写描述式。
- `keep` 的代价：正文搜「嚈哒」搜不到「𫩫哒」。

## 各书实例（只对该书成立，不是通用规则）

### 世界史·古代史编（下卷），2026-09-24/25 全书做完

- 疑字 323 个：AI 看原图判定后改字 69、认可 215；把握低 39 个里 6 个由用户看截图判定改字、2 个用户核纸本认可、31 个用户整批放行。
- 两家都不对的常见：「𫩫哒」被读成「哎/呎/吠/呆哒」（改规范字「嚈哒」）；专名（笈多、憍陈如、波罗痆斯、摩诃剌侘、努比亚、彦悰、黎季犛、札只剌、弘吉剌、木剌夷）；
  「犁镵」读成「犁镰」。PaddleOCR 常见错：己→已、讧→订/江、连接号→一。
- **这本书的扫描件**：「入」起笔细，看上去像「人」（纸本核对 p.11「迁入」、p.28「长驱直入」都是「入」）；「剌」「刺」分辨不出。
  这类字 AI 只判把握低；译名按通行写法「剌」。p.12「所向披靡，」逗号上方有噪点，OCR 读成分号。

### 黄道周集（竖排繁体，中华书局 2017），2026-09-25

- 书不在库里，走「书不在 Obsidian 库里」那条路。疑字 501 个分 10 批：改字 189、认可 198；把握低 93 个里约 35 个请用户整批放行，38 个分四组交用户看图。
- VL 底稿的成批错：竖排「二」读成「一」（数横画）、原书缺字框「□」读成「，」「。」、书名号里的单书名号「〈〉」读成「《》」、「鄤」读成「鄭」、「藺」读成「蘭」。
- 本机 PP-OCR 的成批错（正文不误）：繁体读成简体（漸→渐）、「入」读成「人」、「鄤」读成「鄖」。
- 两个相邻篇目的字被映射对错了位，截图上看成八个字两两互换（儒↔洪、行↔範……）。那是正文把两条篇目的次序颠倒了，逐字对换后结果正确，但要先看整页确认。
- 截图落在注号上、与正文对不上（D 或把握低）的，多半是注的结构问题，交结构核查处理，不在疑字里改。
