# AI 看原图判定 OCR 疑字

逐字映射里的 OCR 疑字有两档：「两家读法不一致」（MinerU 与 PaddleOCR 读得不同，错字最集中）与「两家一致但把握低」
（多是认对的生僻字）。本流程让看得懂图的模型逐个看原书图像判定，再按站长定的规则改正文、写校勘账本（笔记1012 插件）。
只在站长要求时做。以一本书为单位，一口气做完的流程如下。

## 整本流程

1. **截图**：`python -X utf8 scripts/doubt_crops.py <书文件夹> 1000 <输出目录>`。读书文件夹里的
   `校勘/<书名> OCR疑字.md`（先在插件里生成或更新）与 `_数据/`，两档都收（manifest 的 `kind` 为 `disagree` / `low`），
   按逐字映射截原图（整行附近 + 单字放大），每 5 个拼一张 `sheet-N.png`，写 `manifest.json`。只读笔记库。
2. **并行判定**：按约 50 个字（10 张拼图）一批，**每批一个全新子代理**，几批同时跑（一本约 300 字分 6 批，每批一两分钟）。
   子代理只把结果写成 `judgement-bK.json`，回报一行计数，不回贴表格，免得撑满主会话。
   发给子代理的提示词与结果格式用现成模板 [judging-prompt.md](judging-prompt.md)，填好书名、编号范围和「本书注意」即可。
3. **合并与过目**：`python -X utf8 scripts/merge_judgement.py <输出目录>` 合并目录里全部 `judgement-bN.json`（批数不限）为 `judgement.json`，
   按「原字→改作」分组列出要改的（把握高的 B/C）、原书误植、把握低的清单。编号重复、缺号、字段不全时它只列问题、不写文件，
   让那一批补齐再合并。主会话过一遍分组：专名、异体、常用字改得合不合文意。
4. **执行**：在站长的 Obsidian 里经命令行 eval 跑 `scripts/apply_judgement.js`（需要笔记1012 插件）：
   ```
   window.__judgement = { dir: "<输出目录>", variants: "normalize", by: "AI 看原图判定" };
   eval(require("fs").readFileSync("<skill>/scripts/apply_judgement.js", "utf8"))
   ```
   结果在 `window.__judgementResult`（`applied` 改字、`verified` 认可、`skipped` 把握低未动、`mismatched` 位置对不上）。
   执行前把正文备份一份到输出目录。
5. **把握低的交给站长在对话里判**：`python -X utf8 scripts/pending_sheet.py <输出目录> <编号,编号,…>` 把这些字拼成一张图
   （每处标编号、书上页码、PDF 页码、正文现作），发给站长；站长回一行结论（如「66 入，184 剌」），写成 judgement
   （`by: "站长判定"`、依据「站长看原图截图判定」）再跑 `apply_judgement.js`。只挑「正文可能要改」的几处给站长，
   正文已是规范写法、只是扫描件看不清的，归一类请站长整批放行。
6. **整批放行**：站长同意后，在 Obsidian 里跑 `scripts/verify_remaining.js`
   （`window.__verifyRemaining = { title: "<书名>", by: "站长认可（未核纸本）", basis: "…" }`），
   按当前清单的前后文把剩下的全部认可，清单清零。站长翻纸本核对的个别字用 `scripts/verify_by_owner.js`
   （`window.__ownerVerify = { dir, numbers: [17, 28], basis: "纸本原书作入" }`），判定者记「站长核对纸本原书」；
   它在当前清单里按前后文找回这个字，不依赖截图时的位置，先加 `dryRun: true` 看找到的是不是那一处。

## 判定原则

完整的判定说明在 [judging-prompt.md](judging-prompt.md)。最要紧的一条：**以原图上印的字为准，上下文只作辅助**——曾凭上下文把原书印的「觶」猜成「觿」。
某本书扫描件有已知的特殊情况（见「各书实例」）时，写进那本书提示词的「本书注意」，不当通用规则。

## 执行规则（站长定）

| 判定 | 处理 |
|---|---|
| 把握低，或 D | 不动，交站长（第 5、6 步） |
| A | 认可此字，账本记判定者与依据 |
| A 且 `misprint` | **照录原书，另出校记**：正文不改，校勘记「照录原书的校记」写「原书作X，疑为Y之误」 |
| B / C | 改成原书的字，校勘记「判定与依据」写判定者与依据 |
| 有 `variant` | `variants: normalize`（默认）正文用规范字，校记「原书作𫩫（嚈的异体），改作规范字」；`keep` 正文用原书字形，校记「规范字作嚈」 |

判定者要区分「AI 看原图判定」「站长判定」「站长核对纸本原书」「站长认可（未核纸本）」，读正文的人与 AI 都能看出哪些字经人核过。

## 技术要点

- **位置会挪动**：截图时记的是 UTF-16 偏移。执行时前面改过字、尤其换成扩展区的字（如「顗」→「𫖮」，占两个 UTF-16 单位），
  后面的字会整体挪一位。`apply_judgement.js` 在位置对不上时按前后四字在原位附近找回；仍找不到才记 `mismatched`，不会改错地方。
  上下文里的字本身也可能已改过（如前文「呎」已改成「嚈」），这时要按当前正文重写上下文再找。
- **插件侧**（笔记1012 f554597 起）：改过的字不再按「把握低」标出；认可记录的前后文一侧因附近改字变了，另一侧对得上仍算认可。
- 同一个错字常在一本书里反复出现（古代史编下「嚈哒」30 处），判定时一眼能看出同一字形，合并时按「原字→改作」分组核一次即可。

## 异体字

- 字形收进 Unicode 就能直接打、直接存（例：嚈的类推简化 𫩫 = U+2BA6B，扩展 E 区）。查码位：Unicode Unihan
  `https://www.unicode.org/cgi-bin/GetUnihanData.pl?codepoint=<码位>` 的 kSimplifiedVariant 等字段，或字统网 zi.tools。
- 显示要字体支持扩展区：Windows 自带「宋体-ExtB」（simsunb.ttf）含 𫩫，Obsidian 会自动回退使用。
- 没收进 Unicode 的字形只能写部件描述式（`⿰口厌`），正文用规范字，校记里写描述式。
- `keep` 的代价：正文搜「嚈哒」搜不到「𫩫哒」。

## 各书实例（只对该书成立，不是通用规则）

### 世界史·古代史编（下卷），2026-09-24/25 全书做完

- 疑字 323 个：AI 看原图判定后改字 69、认可 215；把握低 39 个里 6 个由站长看截图判定改字、2 个站长核纸本认可、31 个站长整批放行。
- 两家都不对的常见：「𫩫哒」被读成「哎/呎/吠/呆哒」（改规范字「嚈哒」）；专名（笈多、憍陈如、波罗痆斯、摩诃剌侘、努比亚、彦悰、黎季犛、札只剌、弘吉剌、木剌夷）；
  「犁镵」读成「犁镰」。PaddleOCR 常见错：己→已、讧→订/江、连接号→一。
- **这本书的扫描件**：「入」起笔细，看上去像「人」（纸本核对 p.11「迁入」、p.28「长驱直入」都是「入」）；「剌」「刺」分辨不出。
  这类字 AI 只判把握低；译名按通行写法「剌」。p.12「所向披靡，」逗号上方有噪点，OCR 读成分号。
