# 工作流 B：非现代排印古籍

适用：刻本、旧刊本、抄本、稿本等原页的扫描或影印。即使影印集是现代出版，只要页面未重新排字，仍走本流程；现代重新排字的点校古籍走工作流 A。手写和特殊行款先抽样，已有小样本不能代表全部刻本或抄本。

## 默认验收：页码、多级标题、识字准确

按页保留可核对文字，目录辅助建立卷、篇、节的层级，双读者核对疑字。原有夹注和附注的文字仍需保留，不要求默认恢复复杂脚注链接、字号行款、逐字坐标或 PDF 文字层。用户另外要求时再扩展。

## 1. 页面与识字

抽看目录、正文、夹注和难字页。选择表现更好的文字来源，常用 VL 作初稿，看典作第二读者；已有 MinerU 原生结构、位置框或文字可用于辅助，不能因为字读错就全部弃用，也不能据此自动信任其标题/注区分类。没有可用第二读者时注明覆盖缺口。接口见 [vl.md](vl.md)、[guji-apis.md](guji-apis.md)。

保持逐页次序，先生成按页原稿。每页始终保留 `<!--pdf-page.41-->` 这样的物理页锚点。确认原书页码时另加 `<!--p.12-->`；原叶码如“三上”“二十右”可以照录为 `<!--leaf.三上-->`。把 OCR 读到但未核定的页码放进报告，不把推算或 PDF 页序冒充原页码。

`vl_build.py` 可作轻量起稿工具：默认保留疑似异常文字及待核分类，不自动改卷号；没有印刷页报告时只写物理页锚点。

```powershell
python -X utf8 <skill>/scripts/vl_build.py build --vl-dir <书>/_数据/VL --pdf <书>/书.pdf --segment 1-30:01-原稿.md --writing-mode vertical-rl --out-dir <书>/_数据/过程报告/按页原稿
```

将待核书眉、疑似编造等与原图对照后定点处理，保留正文原字；`<!--?structure-->`、`<!--?vl-suspect-->` 等表示仍需核查，不是可直接交付的完成标记。不强制运行旧版分隔线判脚注、字号判夹注等启发式流程；`--legacy-heuristics` 不属于本流程默认步骤。若逐页手工整理更简单，也可直接使用 VL JSON/TXT 和原图形成按页 Markdown，不要求走完整通用重建器。

## 2. AI 看目录重建多级标题

执行 [toc-headings.md](toc-headings.md)：AI 看目录原页，录入候选树，核对正文页，再应用层级。以原书卷、篇、门类的实际隶属关系为准。不默认将正文第一个短行升成标题，不因卷号重复自动改成下一卷。

目录只列到卷或篇时，更细的小题从正文原图识别并标明依据；目录与正文异名分别记录。缺题、缺页、低把握隶属关系列清单，不编题补页。

## 3. 逐页疑字核对，无需逐行重建

将已经核定标题的稿保存为新快照，建立轻量页级映射，再与第二读者比。页级映射只记录文字属于哪一页，疑字核图可截整页，不需要先完成列框分析。

```powershell
python -X utf8 <skill>/scripts/line_map.py --pdf <书>/书.pdf --md <书>/01-正文.md --page-only --writing-mode vertical-rl --out <书>/_数据/页级映射
python -X utf8 <skill>/scripts/vl_compare.py --book <书> --line-map <书>/_数据/页级映射/line-map.json --kandian "<书>/_数据/看典|1" --pages 1-30 --out <书>/_数据/疑字判定
```

原稿用原 PDF 页号作锚点；抽出小 PDF 测试时，先在原稿里映射回原 PDF 页号，第二读者参数的 `目录|起页` 也要一致。正文改动后刷新映射和疑字，不沿用旧偏移。判定与安全执行见 [quality-and-location.md](quality-and-location.md)、[ai-judging.md](ai-judging.md)。

## 4. 交付

交付正文 Markdown、目录/标题树及核对报告、必要原图、校注和未判疑字。报告说明原件版本、页码/叶码与 PDF 页序对应、标题覆盖、第二读者覆盖及不确定项。

对处理前快照运行 `diff_report.py --before <原稿.md> <成品.md>`；标题层级变化另在目录报告列明，文字改动逐条有原图依据。默认不制作文字层、不展开图表精细重建或脚注工程；遇到图片、缺字框和难以转录的内容，保留原图定位，不能直接丢掉。
