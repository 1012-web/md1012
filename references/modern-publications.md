# 工作流 A：论文和现代出版物

适用：论文、研究专著、教材，以及现代重新排字的点校/整理古籍。横排或竖排、有标点或无标点都不改变材料归属。现代影印旧刻本、抄本而未重新排字的页面走工作流 B。

## 验收目标

忠于这份出版物的文字；恢复原有脚注及引用位置、多级标题、页码、图片和表格，原有标点照录；保存改动依据。只做局部任务时按用户范围验收，不要求重新解析全书。

## 解析与原生信息恢复

1. 本地预检并抽看正文、注区、目录、图表和特殊页。现代竖排本先检查结构分类，不把“有坐标”当作标题、脚注均已正确。
2. 常规选择 MinerU 作结构底稿，VL 作第二读者；服务及上传说明见 [mineru-api.md](mineru-api.md)、[vl.md](vl.md)。已有缓存就直接利用。只在确实需上传时处理缺失的凭据，离线检查不跑服务状态查询。
3. 从 `layout.json` / `*_middle.json` 提取正文和原生结构；`discarded_blocks` 中的脚注等一并检查。`full.md` 只作对照，不作完整正文源。详细字段见 [mineru-outputs.md](mineru-outputs.md)。
4. `probe.py` 出脚注圈码、跨页断段、目录缺题等候选，核原图处理；`build.py` 忠实合并已有信息，不另用一套猜测替换可用的脚注与表格。

```powershell
python -X utf8 <skill>/scripts/probe.py <MinerU目录>
python -X utf8 <skill>/scripts/build.py <MinerU目录> -o <书>/_数据/过程报告/_skeleton.md
```

分卷骨架用 `merge_skeletons.py` 按原书顺序衔接，检查接缝和脚注编号。表格保留 HTML 行列结构及原图；图片用 `copy_images.py` 只复制被引用项，不删除原始 ZIP 或结果。

## 目录与多级标题：必经的共用步骤

先让 AI 看目录那几页原图，形成候选标题树；在初稿中定位正文标题，核对父子关系、页码与题名，再定点应用层级。完整步骤、outline 格式和提示见 [toc-headings.md](toc-headings.md)。没有目录的论文用正文明确标题形式，注明依据，不强造目录或更多层级。

## 文字与结构校核

- VL 或其他第二读者提供疑字，不直接覆盖正文。看原图区分 OCR 错读与出版物本身误印；异体字按本书已有方针。
- 脚注检查正文注号、定义和原注区是否对应。标题、注、图表、正文发生混淆时定点修复，不只核文字数量。
- 标点缺失先看原图：原书本来没有就不补；文字层映射损坏才选择读图恢复或重新 OCR。脚注不按模型语义补标点。
- 如果 MinerU 文字差但框架可用，可用 VL 协助识字；如果结构也失效，用按页 VL 稿作为替代起点，再核出版物实际脚注和结构。本书仍属于工作流 A，不能因此套用工作流 B 的简化验收。
- 通用“结构适配器”不是前提；按现有原生信息和必要的局部核图完成任务。结构核查工具见 [structure-audit.md](structure-audit.md)，仅运行本次需要的项目。

## 交付与检查

`split_book.py` 可整理为正文一份、卷首书末另存；用户明确要求时才按章拆分。论文用 `--level 2`，书目信息由 `--meta` 明确给出。检查 `_split_report.txt` 的去向和页码，避免将序论等误归卷首。

```powershell
python -X utf8 <skill>/scripts/verify.py <成品.md>
python -X utf8 <skill>/scripts/diff_report.py <MinerU目录> <成品.md>
```

改用 VL 起稿时，保留整理前快照，用 `diff_report.py --before <原稿.md> <成品.md>`；原始 VL 响应与整理日志一同保留，不仅比较已经过滤过的正文。

按 [quality-and-location.md](quality-and-location.md) 做疑字与来源定位。现代出版物通常做逐行映射；文字层 PDF 只在用户需要时生成。报告列出脚注、标题对应、图表、页码、第二读者覆盖、已改内容和未完成项。
